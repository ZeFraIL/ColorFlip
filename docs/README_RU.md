## 🎯 Цель проекта
*   **Какую задачу решает приложение:** Представляет собой увлекательную логическую головоломку, в которой игрок должен привести все клетки поля к одному цвету.
*   **Почему эта задача важна:** Логические игры способствуют развитию когнитивных навыков и помогают снять стресс.
*   **Целевая аудитория:** Любители головоломок всех возрастов, ищущие быструю интеллектуальную разминку.

---

## 📌 Требования к приложению
### Функциональные требования
*   Игровое поле 5x5 с двумя чередующимися цветами.
*   При нажатии на квадрат меняется цвет его соседей (сверху, снизу, слева, справа).
*   Счетчик шагов для отслеживания прогресса.
*   Кнопка сброса для начала новой игры.
*   Режим "Блиц": испытание на время (30 секунд).
*   Условие победы: завершение игры, когда все квадраты становятся одного цвета.

### Нефункциональные требования
*   **Производительность:** Мгновенный отклик интерфейса на нажатия.
*   **Удобство использования:** Минималистичный и интуитивно понятный интерфейс.
*   **Надёжность:** Стабильная работа таймера и сохранение состояния в рамках сессии.

## 🧠 Общая архитектура
*   **Выбранный подход:**  
    – MVC (Model-View-Controller)
*   **Почему выбран именно он:**  
    Приложение достаточно простое, поэтому монолитная структура Activity обеспечивает прозрачность кода без избыточного усложнения. `MainActivity` выступает одновременно контроллером и представлением, а массивы данных (например, `colorState`) выполняют роль модели.
*   **Основные компоненты системы:**
    – `MainActivity`: Управляет UI, логикой игры и таймером.
    – `GridLayout`: Динамически отрисовывает игровое поле.

## 🧩 Подробное описание классов
### 📌 Класс: MainActivity
*   **Роль:** Основная точка входа и игровой контроллер.
*   **Ответственность:** Инициализация сетки, обработка нажатий пользователя, управление таймером и проверка условий победы.
*   **Основные методы:**
    – `onCreate()`: Настройка начального интерфейса.
    – `initializeGrid()`: Создание случайного поля и сброс счетчиков.
    – `onSquareClicked()`: Реализация логики "переворота" цвета.
    – `checkWinCondition()`: Проверка, все ли клетки одного цвета.
    – `startTimer()`: Управление обратным отсчетом в режиме Блиц.
*   **Взаимодействие с другими классами:** Взаимодействует с компонентами Android SDK, такими как `GridLayout`, `View` и `CountDownTimer`.

## 🔄 Диаграмма работы приложения
1. Пользователь открывает приложение.
2. Генерируется сетка со случайными цветами.
3. Пользователь нажимает на квадрат.
4. Соседние квадраты меняют цвет.
5. Количество шагов увеличивается.
6. Система проверяет условие победы.
7. Если Да -> Показывается уведомление "You Win!".

## 🎨 UI/UX анализ
*   **Почему интерфейс сделан именно так:** Сеточные головоломки наиболее понятны, когда игровое поле занимает центральную часть экрана.
*   **Какие принципы использованы:**
    – **Простота:** Отсутствие сложных меню, игра начинается сразу.
    – **Логичность:** Элементы управления (Reset, Blitz) расположены в доступных местах.
    – **Доступность:** Крупные элементы управления удобны для нажатия.
*   **Что можно улучшить:** Добавить анимацию смены цвета и звуковые эффекты.

## ⚙️ Работа с потоками
*   **Используются:** `CountDownTimer`.
*   **Почему выбран этот способ:** Это удобный высокоуровневый API Android для работы с обратным отсчетом, который автоматически синхронизируется с главным (UI) потоком.
*   **Как предотвращаются:**
    – **Зависания (ANR):** Игровая логика легковесна и не блокирует поток.
    – **Утечки памяти:** Таймер останавливается (`cancel()`), когда он больше не нужен.

---

## 💾 Работа с данными
*   **Где хранятся данные:** В оперативной памяти (массив `int[][] colorState`).
*   **Почему выбран этот способ:** Состояние игры временно и не требует сохранения между запусками приложения в данной версии.
*   **Как обеспечивается:**
    – **Сохранность:** Жесткая проверка границ массивов.
    – **Корректность:** Сброс состояния при каждой новой инициализации.
